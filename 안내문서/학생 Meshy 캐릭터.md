# 학생 Meshy 캐릭터

2026-09-19 기준, 시작 화면에서 선택할 남학생·여학생을 각각 실사풍과 귀여운형으로 제작했습니다. 사용자 요청에 따라 준비한 4종 기준 이미지를 Meshy API의 이미지→3D 생성, 휴머노이드 리깅, 애니메이션 생성으로 처리한 결과입니다. 실사풍도 생성 캐릭터이며 실제 학생을 스캔한 모델은 아닙니다.

## 배포용 자산

파일은 `웹학교/캐릭터모델/`에 있습니다. 아래 크기는 압축 전 GLB 파일 크기입니다.

| 선택 ID | 파일 | 최적화 전 | 최적화 후 |
| --- | --- | ---: | ---: |
| boy-realistic | 남학생-실사풍.glb | 7,838,368 B | 2,897,692 B |
| boy-cute | 남학생-귀여운.glb | 7,897,904 B | 2,731,372 B |
| girl-realistic | 여학생-실사풍.glb | 8,211,632 B | 3,135,688 B |
| girl-cute | 여학생-귀여운.glb | 7,583,960 B | 3,494,800 B |

각 파일에는 스킨 1개와 `Idle`(대기), `Run_02`(달리기), `Jump_Run`(점프), `Big_Wave_Hello`(인사) 동작이 들어 있습니다. 텍스처는 2048×2048 WebP 1장으로 최적화했습니다. 4종 합계는 31,531,864 B에서 12,259,552 B로 약 61% 감소했습니다.

앱에서는 원본의 금속·발광 재질을 비금속 무광 재질로 조정합니다. 축소 화면에서 머리카락·옷의 일부 UV 경계가 가는 선처럼 보일 수 있습니다. 원본과 최적화 텍스처를 비교했으며, 최적화로 새로 생긴 경계나 중복 메시·뼈대 가중치 불일치는 발견되지 않았습니다.

## 앱 연결과 캐시

`웹학교/학생캐릭터.mjs`에서 선택 ID를 GLB에 연결합니다. 요청한 모델의 로딩 Promise를 종류별로 메모리 캐시하고, 실패하면 캐시에서 제거하여 재시도할 수 있게 합니다. 미리보기와 플레이 캐릭터는 뼈대를 따로 복제하여 자세가 서로 영향을 주지 않도록 합니다. 기존 저장값 `boy`·`girl`은 각각 귀여운형으로 연결합니다.

달리기·점프의 위치 이동은 앱의 이동·충돌 처리에 맡기고, 애니메이션의 루트 이동을 정리하여 캐릭터가 이중으로 이동하지 않게 합니다. 이 문서의 자산 완성과 공개 서비스 반영은 별개이며, 공개 배포 성공 및 실제 동작 검증은 최종 배포 기록에서 확인합니다.

## 제작 기록과 연결

작업공간의 `output/student-characters/optimization-report.json`에 파일 크기·스킨·클립·텍스처 검사 결과가 있고, 같은 폴더의 `meshy-tasks.json`에 생성 작업 기록이 있습니다. 작업 기록에는 만료되는 다운로드 URL이 포함될 수 있으므로 공개 문서에 복사하지 않습니다. 이번 API 잔액은 18,070에서 17,862로, 총 208 크레딧을 사용했습니다.

공식 `@meshy-ai/meshy-mcp-server@0.5.1`을 로컬 Codex의 `meshy` 서버로 등록했고, MCP 초기 연결과 도구 24개 조회를 검증했습니다. 주요 도구는 이미지→3D, 상태 조회, 리메시, 리깅, 애니메이션, 모델 다운로드입니다. 현재 진행 중인 Codex 세션에는 새 도구가 즉시 노출되지 않을 수 있으며, 새 세션 또는 앱 재시작 후 사용할 수 있습니다.

API 키는 Windows 사용자 환경변수 `MESHY_API_KEY`에 두며, `C:/Users/Mijin/.codex/tools/start-meshy-mcp.ps1`이 실행 시 읽습니다. 키를 MCP 설정·프로젝트·브라우저 코드에 기록하지 않습니다. 앱은 완성된 GLB만 사용하므로 공개 서버에 Meshy 키나 MCP 런처를 넣을 필요가 없습니다. 모델에 별도 오픈 라이선스를 부여하는 문서는 아닙니다.
