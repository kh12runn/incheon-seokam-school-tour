# 기존 학교를 보존하는 실사 확장 설계

2026-09-10 · 설계/보관 구조 준비 단계. 후속 사용자 지정으로 첫 대상은 **6-4 교실(4F_6-4)**로 확정했습니다. 실제 Splat 없음, Viewer 미설치. 이 문서의 '향후' 항목은 구현 완료가 아닙니다.

## 1. 역할과 적용 순서

| 계층 | 목적 | 현재 / 향후 |
|---|---|---|
| 학교 Mesh | 전체 공간·캐릭터·계단·벽 충돌·자유 탐험 | 현재 그대로 유지 |
| Texture Bake | 선택한 메시 표면의 실사 마감 | 정면 사진과 UV 준비 후 구역별 추가 |
| 360 Panorama | 촬영 지점의 빠른 실사 확인 | 기존 자료/모듈 보존; 현재 UI 연결은 해제된 상태 유지 |
| SuperSplat | 사용자가 지정한 중요 공간의 실사 심화 | 실제 Splat 검수 후 별도 뷰어로 추가 |
| PLY / SPZ | 학교가 소유하는 보존 원본 | 로컬 보관·해시·별도 저장장치 백업 |
| SOG | 검수·최적화된 웹 서비스 파생본 | 원본 대체가 아니며 준비 후에만 배포 |

학교 전체나 모든 일반 교실을 Splat으로 바꾸지 않습니다. 도서관·다목적실·4층 복도 등은 **후보일 뿐**, 사용자 지정 전에는 장면을 등록하지 않습니다. Gaussian 결과를 메시 텍스처로 변환하는 작업도 하지 않습니다.

## 2. 이번에 준비한 보관 구조

`assets/splats/안내.md`에 경로와 보관 원칙을 기록했습니다. 요청한 기술 경로 `assets/splats/`만 영문으로 유지하고 사람이 사용하는 내부 폴더는 한글입니다.

- `장면목록.json`: `enabled: false`, 6-4 교실 준비 항목 1개. 현재 표현은 `mesh`, 향후 계획은 `hybrid`이며 panorama/splat 기능은 비활성입니다.
- `장면등록서식.json`: 실제 장면이 아닌 서식. 파일·ID·설치 버전·복귀 위치는 `null`, 정렬은 `unverified`.
- `장면준비서식/원본보존`, `웹용경량본`, `충돌모델`, `뷰어`: 안내문만 존재하는 폴더 서식.
- 새 파일은 기본 Git 제외, 현재 `assets/splats/` 전체는 Railway 업로드 제외. 필요한 개인정보 없는 안내/서식만 추적.

새로운 `photos/` 저장소를 중복 생성하거나 기존 사진을 옮기지 않습니다. 텍스처 촬영이 시작되면 기존 한글 촬영 폴더의 해당 공간 아래 `정면사진/원본`과 `정면사진/보정본` 등으로 분리하는 안을 사용합니다. `panorama/textures/processed`는 목적 구분에 대응하며 새 영문 촬영 폴더를 강제하지 않습니다. 현재는 이 추가 촬영 트리를 생성하지 않았습니다.

## 3. 등록 데이터와 활성화 조건

장면의 `spaceId`는 기존 `공간자료/spaces.json` 또는 최신 웹 보정 후 공간 ID와 연결합니다. 예시 `4F_CORRIDOR_01`을 실제로 존재하는 ID라고 가정하지 않습니다. 기존 ID와 일치하지 않으면 명시적 대응표를 검수해야 합니다.

`source`는 프로젝트 루트 기준 로컬 원본 경로, `sog/collision/viewer`는 추후 공개 허용 경로, `returnLocation`은 검증된 학교 기본 복귀 위치입니다. 현재는 전부 미정입니다. 실제 `source`·해시·검수 세부 정보는 Git 제외된 `<공간명>/원본보존/장면작업기록.json`에 기록합니다. 공개 Git의 `장면목록.json`이나 브라우저에는 원본 경로·개인정보 검수 내용을 옮기지 않습니다. 향후 활성 장면에서 필요한 공개 필드만 검수하여 추출합니다.

`spaceModes`에는 향후 `{spaceId, displayMode, features, panoramaIds, splatSceneIds}`를 둡니다. `displayMode`는 `mesh | panorama | splat | hybrid`, `features`는 `{mesh, panorama, splat}`입니다. 새 등록부는 기존 공간/사진 목록을 대체하지 않고 참조합니다. 현재 실제 목록은 비어 있습니다.

향후 실사 버튼 노출 조건은 다음을 모두 충족해야 합니다.

1. 사용자가 지정한 공간이며 장면/공간 ID가 검증됨.
2. 실제 SOG·단순 충돌 GLB·고정 버전 Viewer가 존재하고 정상 로드됨.
3. 개인정보·좌표 정렬·충돌·성능·공개 승인 상태가 모두 통과함.
4. 활성 장면의 배포 허용 목록과 라우팅이 준비됨.
5. 사용자가 해당 공간의 진입 영역 안에 있으며 다른 메뉴/뷰어 전환 중이 아님.

파일이나 검수가 없으면 버튼을 만들지 않습니다. 실패 시 기존 학교로 돌아갈 수 있어야 하며 가짜 장면·체험용 대체 Splat을 학교 실사로 제시하지 않습니다.

## 4. Viewer 선택과 API 확인

2026-09-10 확인한 공식 Viewer README는 `content`로 SOG를, `collision`으로 GLB 또는 voxel 자산을 지정하는 방식을 설명합니다. 이는 **공식 저장소 현재 문서 확인**이지 이 프로젝트에 설치·검증된 버전을 뜻하지 않습니다. 실제 도입 때 패키지 버전 또는 커밋을 고정하고 동일 버전의 문서/코드로 재확인합니다. [공식 Viewer README](https://github.com/playcanvas/supersplat-viewer/blob/main/README.md)

자체 호스팅 출력에는 단일 HTML과 ZIP Viewer App이 있습니다. 이 프로젝트는 자산을 별도로 관리·캐시하기 쉬운 ZIP/정적 파일 구성을 우선 검토합니다. 원본이 HTML 안에 숨겨져 배포되지 않도록 포함 데이터를 검사합니다. [공식 자체 호스팅 안내](https://developer.playcanvas.com/user-manual/supersplat/viewer/self-hosting/)

예정 경로 `/splat/<검증된-slug>/`는 **아직 서버에 존재하지 않습니다**. 예시 `?content=scene.sog&collision=collision.glb`는 지원 문서와 부합하지만, 모든 버전/내보내기 결과에서 자동 적용된다고 가정하지 않습니다. 등록부의 `splatTransform`도 Viewer 내장 API가 아닌 본 프로젝트의 저작용 계약입니다.

외부 iframe 공유 링크를 핵심 데이터 원본으로 사용하지 않습니다. 실제 자산과 Viewer를 학교가 보관하고 같은 Railway 서비스에서 호스팅하는 방향입니다. 기본 학교의 Three.js와 Viewer의 렌더러·이벤트는 분리하고 동시에 렌더링하지 않도록 합니다.

## 5. 충돌과 좌표 정렬

우선 후보는 **Blender 기반 단순 GLB**, 비교 후보는 voxel입니다. 지정 구역만 만들며 바닥·벽·필요 계단·통제 구역을 포함합니다. 문을 막지 않고 책상/의자 등의 세부는 제외합니다. 반드시 막아야 하는 큰 가구는 별도 단순 상자로 처리합니다. 현재 학교의 책상/의자 충돌은 변경하지 않습니다.

주의: 현재 웹 계단·개구부·1층·엘리베이터 보정은 Blender 저장본에 반영된 상태가 아닙니다. 충돌 파생본을 만들 때 이 보정과 현장 배치를 대조해야 합니다. 현장 치수와 근사 학교 모델이 다르면 Splat에 맞춘 전용 충돌 파생본을 만들고 기본 학교 전체를 억지로 변형하지 않습니다.

- 학교 물리 기준: Blender Z-up, 미터, `(x,y,z)`.
- 학교 렌더 변환: `(x,y,z) → (x,z,-y)`.
- Viewer 충돌 인터페이스는 Y-up 오른손 좌표를 기준으로 합니다. [공식 충돌 인터페이스](https://github.com/playcanvas/supersplat-viewer/blob/main/src/collision/collision.ts)
- GLB exporter가 이미 Y-up 변환했는지 확인하여 축 변환을 두 번 하지 않습니다.
- 등록부 회전은 라디안, XYZ 순서로 기록하고 단위·축·내보내기 설정을 함께 보관합니다. 실제 도구의 각도 표기는 도 단위일 수 있으므로 경계에서 명시적으로 변환합니다.
- 수식상 `P_viewer = T · R · S · A · P_source`. `A`는 확인된 원본 축 변환이며 임의로 Z-up으로 가정하지 않습니다. Splat/GLB의 실제 출력 좌표를 읽어 정렬합니다.
- 바닥 모서리·문틀 양끝·높이 기준 등 최소 3개의 비공선 대응점과 추가 검증점을 수집합니다. 실측 기준 길이로 스케일을 맞추고 바닥/수직/높이 잔차를 기록합니다. 통과 기준은 문 유효 폭과 캐릭터 충돌 반경에 맞춰 현장 구역별로 정합니다.
- 전부 0/1인 기본 변환은 '정렬 완료'가 아닙니다. 정렬된 **파생본**으로 내보내거나 고정 버전 Viewer가 지원하는 변환 경로를 별도로 구현/검증합니다. 보존 PLY/SPZ를 덮어쓰지 않습니다.

통과할 시험: 문 통과·벽 차단·바닥 이탈 방지·계단/단차·통제 공간 차단·복귀점 유효성. voxel 방식은 누락 벽·좁은 문 폐쇄 여부를 GLB 방식과 비교한 후 결정합니다.

## 6. 기존 학교와 실사 간 왕복

현재 `schoolTour.getState()`는 읽기 전용 진단입니다. 위치 변경용 `schoolTour.test`는 루프백 `?test=1`에서만 존재하므로 공개 복귀 구현에서 사용하지 않습니다.

향후 게임 모듈 내부에 작은 '전환/복귀' 경계를 추가합니다. 이동 시스템 자체를 재작성하지 않습니다.

1. 출발 시 장면 ID, 위치 `(x,y,z)`, `yaw/pitch`, 카메라 거리, 캐릭터, 구조 버전, 시각을 저장합니다. 점프 중이라면 안전한 착지/복귀 지점을 먼저 확보합니다.
2. 입력 키·속도·점프·인사를 정리하고 마우스 잠금을 해제한 뒤 학교 렌더/입력을 일시정지합니다.
3. 별도 Viewer를 로딩하고 성공한 뒤 화면을 전환합니다. 실패/취소/시간 초과 시 학교로 복귀합니다.
4. 복귀 버튼이나 브라우저 뒤로가기는 중복 실행을 막는 단일 복귀 경로로 처리합니다. Viewer의 렌더 루프·이벤트·GPU 자원을 해제합니다.
5. 저장 위치를 현재 `world.candidate`로 검증하고 시점/캐릭터를 복원합니다. 구조 버전 불일치·잘못된 숫자·벽 안 좌표는 등록된 안전한 복귀점으로 대체합니다.
6. 마우스 잠금은 브라우저의 사용자 동작 조건을 준수하고 기존 자동 시점/거절 시 대체 처리를 재사용합니다. Esc 강제 재잠금으로 브라우저의 탈출 동작을 막지 않습니다.

학교 페이지가 유지되는 경우 메모리 스냅샷을 사용합니다. 별도 경로 탐색 시에는 같은 출처의 `sessionStorage`에 버전/만료가 있는 최소 상태를 저장하고 한 번 복원한 뒤 지웁니다. `returnUrl`을 외부 URL 그대로 받아 이동하지 않습니다. 전체 상태나 개인정보를 쿼리스트링에 넣지 않습니다. 현재는 왕복 기능을 구현하지 않았습니다.

## 7. Texture Bake 파이프라인

원본 → 보정 사본 → 선택 구역 메시/UV → Diffuse Color Bake → 웹용 파생 텍스처 순서로 관리합니다.

- 벽·문·칠판·사물함 등은 가능한 정면 고해상도 일반 사진을 우선합니다. 360 사진은 주변 관계 파악과 파노라마용이며 모든 면의 베이크 원본으로 강제 사용하지 않습니다.
- 원본 수정 없이 렌즈 왜곡·수직 보정본을 따로 만들고 촬영 방향/대상 면/공간 ID를 기록합니다.
- 지정 구역의 원본 사본에 투영용 UV와 베이크용 UV를 분리하고, Color만 베이크하여 촬영 조명과 웹 조명이 중복되지 않도록 비교합니다.
- 2048/4096px를 후보로 테스트하되 장치 메모리·가독성·압축 후 품질을 측정합니다. 보존용 결과와 웹용 결과를 분리합니다.
- 현재 `export_web.py`는 UV/사진을 전달하지 못합니다. 선택 구역 시각용 GLB 또는 별도 UV 메시 경로를 추가하고 기존 충돌 세계와 공간 ID를 유지하는 방식이 필요합니다. 이 단계에서 기존 exporter를 바꾸지 않습니다.
- 사진으로 확인되지 않는 면은 '확인 필요/근사 마감'으로 기록합니다. 생성 보완은 실제 학교 기록과 구별하고 원본이나 보존용 Splat에 섞지 않습니다.

## 8. 배포·성능·개인정보 통과 기준

첫 장면은 단일 SOG로 측정합니다. LOD, 여러 동시 Splat, 전체 학교 스캔은 현재 도입하지 않습니다.

- 사용 버전과 실제 단말에서 WASD/Mouse, 지원되는 경우 Click-to-Walk·터치 이동, 충돌 동작을 확인합니다. 기본 학교와 동일 조작/아바타가 자동 제공된다고 약속하지 않습니다.
- 다운로드 용량, 첫 화면까지 시간, CPU/GPU 메모리, 평균/낮은 프레임 구간, 진입/복귀 반복 누수를 PC와 실제 휴대전화에서 기록합니다. 낮은 성능/미지원이면 기존 Mesh로 복귀합니다.
- 현재 `배포최적화.mjs`는 JSON 안의 임의 자산 URL이나 동적 Viewer 의존 파일을 자동 수집하지 않습니다. 승인된 장면별 SOG/GLB/settings/JS/CSS/필요한 worker·wasm을 명시적으로 수집하는 확장이 필요합니다.
- 서버는 `/splat/<slug>/`를 검증된 Viewer index로 연결하고 GLB/SOG MIME을 추가해야 합니다. URL traversal·비공개 원본·미검수 장면은 계속 차단합니다. Range 등 추가 전송 기능은 실제 Viewer 필요에 맞춰 검증합니다.
- 배포 허용 목록은 원본 폴더를 재귀 복사하지 않습니다. Railway의 현 서비스·도메인·healthz는 유지하고 필요한 변경만 추가합니다. 이 문서는 지금 배포 권한을 확대하거나 자동 배포를 수행하지 않습니다.
- 촬영은 가급적 무인 시간에 하고 학생 얼굴/이름/사진/작품 이름/문서/모니터를 사람이 검수합니다. 편집용 업로드도 외부 전송이므로 개인정보와 권한 확인이 선행되어야 합니다. AI 제거만으로 통과시키지 않습니다.

## 9. 다음 단계에 필요한 입력

사용자가 **첫 시범 공간 하나**를 지정하고 실제 PLY/SPZ를 제공하거나 촬영/재구성 방식을 함께 정합니다. 360 영상만으로 이미 Splat이 완성된 것으로 취급하지 않습니다. Texture 시험을 먼저 진행한다면 지정한 벽/구역의 정면 사진이 필요합니다.

현재 첫 공간은 6-4 교실입니다. 후속 사용자 승인으로 **기존 두 사진만 사용하는 웹 사진 마감**을 적용하고 Splat은 보류했습니다. 6-4 추가 촬영을 요청하지 않습니다. 다른 교실은 사용자가 사진을 줄 때 별도로 반영하며 공통 교실 배치에 6-4 변경을 전파하지 않습니다. Splat 기능/뷰어/버튼은 비활성으로 유지합니다.
